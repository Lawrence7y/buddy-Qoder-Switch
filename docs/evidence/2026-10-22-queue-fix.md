# 2026-10-21：ZCode 空结束定位与修复

## 本次结论

已找到并修复一条可复现的“没有可见回复却正常结束”路径：
Qoder 的 dfmodel 上游返回排队错误，旧 Anthropic 转换器丢弃 error 帧，
随后合成 message_start → end_turn → message_stop。
这与此前 DSML 工具文本泄漏是不同的问题。

已构建并启动 `20261021-queue-fix`。仍使用同一预览数据目录、13 个账号和用户配置的
58892 统一入口；旧版与 Harness 没有被自动恢复。

## 真实证据

- 预览版原请求日志中 15 条 dfmodel 失败均带 10605/CALL_COUNT_LIMIT、isQueued=true。
  没有生成 tokens；日志将其记为 502，实际对流式调用者已先发送 HTTP 200。
- ZCode 日志明确记录 baseURL=http://127.0.0.1:58892、providerKind=anthropic、
  modelId=qoder-cn:dfmodel；23:57:39 的 main_turn 被 SDK 记为 completed。
- 对应网关请求在 23:57:39.080 记为排队错误，ZCode 在 .084/.085 记为流成功完成。
- 新增回归测试在修复前失败，实际输出空 end_turn/message_stop；原始失败输出保留于
  `queue-before-fix.log`。
- 脱敏关联摘要：`queue-evidence-summary.json`。没有导出 RA2 提示词、令牌或配置密钥。

## 修改

1. 在发送成功响应前读取首个有效增量：上限 256 KiB / 60 秒，预读的正常原始字节原样回放。
2. 递归解包有界的嵌套 JSON；10605 / CALL_COUNT_LIMIT 是模型排队，返回 HTTP 429、
   Anthropic rate_limit_error 及 Retry-After，不误标 access token 死亡。
3. 冷却该模型并采用上游等待时间，不自动换模型，不在网关内部持续重试排队请求。
4. Anthropic 流中的错误与传输中断发终态 error 事件，不再合成成功结束。
5. Qoder 原始流读取失败明确输出错误；空流和首帧前结束不再成为成功补全。

正常 SSE 逐字回放、既有工具恢复和协议转换链保留。

首轮工具的标记检查是对整段 SSE 搜索，不能证明逐片拼接后的文本。
修正诊断器后，只补发一次 dfmodel；保存拼接检查结果为
`queue-live-probe-rendered.jsonl`、原始合成诊断回复为 `queue-live-dfmodel.sse`。
这些诊断调用没有携带 RA2 任务内容，没有向原 ZCode 会话发消息或执行工具。

本轮真实生成验证只证明极短回复可见；未把它外推为 ZCode 的二十轮编码验收。
上游之后仍可能排队。修复保证正确报告限流，不能保证供应方持续有容量。
