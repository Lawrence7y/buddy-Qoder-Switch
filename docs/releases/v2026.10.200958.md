## ✨ 三个平台的模型清单都声明上下文大小

- `/v1/models` 现在统一带 `context_length`：WorkBuddy 取目录的 `context_window`、Qoder 取模型元数据的 `max_input_tokens`、Trae 取官方目录的逐模型上限。OpenAI 兼容客户端读这一个字段就能知道每个模型能装多少。
- 原字段（`context_window` / `max_input_tokens`）保留，老客户端与管理面不受影响。

## 🚦 为什么只有 Trae 有 Max Mode 开关

- Max Mode 是 Trae 上游的**请求级布尔字段**：同一个模型有 `dev`（`__dev` 通道实际窗口）与 `max`（上限）两个值，才需要「开 / 关」。
- WorkBuddy 与 Qoder 的目录只有一个上限值，没有第二个模式可切 —— 所以模型页给的是「上下文上限 · 按目录声明」只读说明卡，而不是一个点了没反应的开关。
- 模型页的「上下文」列三家都有：`200k / 400k / 1M / 982k` 直接可见；Trae 关闭 Max Mode 后回到 `dev`。

## 🛠 内部

- WB 模型条目抽成 `routes::models::model_entry`，独立网关与统一网关共用一份（避免两处 JSON 漂移）。
- 版本号统一为 2026.10.200958（19 处载体校验通过）。
