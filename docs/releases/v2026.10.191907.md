## 🐛 修复：统一网关（57892）重启后必须手动「关一下再开」

- 症状：配置里已启用、界面开关也是绿的，但彻底退出再启动后 57892 没有监听，客户端一直「生成中」，网关侧一条日志都没有。
- 根因：`setup()` 只登记了网关运行时句柄，漏了「按配置拉起监听」那一段 —— 只有「保存配置」这个动作能启动它。
- 修复：启动时补齐 `apply()`，并新增跨两侧宿主（桌面端 / web 端）的回归护栏，任何一侧漏掉测试即变红。
- 可观测：网关页「启用统一网关」一行现在显示**真实监听状态**（监听中 / 未监听），开关绿但端口没人 accept 一眼可见。
- 升级后无需操作：配置启用即启动监听。

## ✨ Trae 上下文与 Max Mode：逐模型从官方目录读取，不再是统一 1M（issue #53）

- 此前清单只声明 200k（取客户端缓存的 `context_window_size.default`），而 Max Mode 是请求级布尔字段，客户端里无从选起。
- 网关现在重放 Trae 官方模型目录接口，读取每个模型的 `dev`（`__dev` 通道实际窗口）与 `max`（Max Mode 上限）。
- `max > dev` 的模型在请求时注入 `is_max_mode`，`/v1/models` 直接声明它**自己的**上限：`glm-5.3` 1M、`mimo-v2.6-pro` 982k、`Doubao-Seed-2.1-Turbo` 仍是 256k —— 上限各不相同。
- 目录缓存 24 小时；拉不到时静默沿用旧缓存，没有缓存就按客户端默认窗口声明，**不猜数字**。
- 模型名保持不变：基名（`glm-5.3`、统一入口 `trae-cn:glm-5.3`）即可，没有 `-max` 之类的影子模型。

## 📊 三个平台的模型表都显示「上下文」

- WorkBuddy：目录 API 的 `context_window`（同一份目录里 256k / 960k / 1M 都有）。
- Qoder：模型元数据的 `max_input_tokens`。
- Trae：上面那份 `dev/max`（开启 Max Mode 后显示该模型自己的上限，并注明默认值）。
- 未知时显示 `—`，不编造数字；原型（`docs/prototype/buddy-switch-prototype.html`）同步补齐三平台交互与 `?max=off` 对照。

## 🔧 健康检查统一为 `/health`（`/healthz` 保留为别名）

- 四条网关此前 3:1 分裂（WB / Qoder / 统一入口用 `/healthz`，Trae 用 `/health`），现在统一为 `GET /health`。
- `/healthz` 作为兼容别名继续可用：同一处理器、返回体逐字相同，已写死它的探活脚本不用改。
