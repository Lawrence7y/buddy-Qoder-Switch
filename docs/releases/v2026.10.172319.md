## 🚀 WorkBuddy 账号池「随机」档回来了

有用户反馈 WorkBuddy 国内版 → 网关 → 账号池的「指定账号」下拉只剩两档，而 Trae / Qoder 同位置是三档 —— 少的正是「随机」。后端「在合格账号里均匀抽签」的能力一直都在，只是 WorkBuddy 页从「账号策略卡」迁到「账号池卡」时漏传了这一档，界面上看不到，并排看 Trae 页还像「本来就没有」。

- 现在三平台同一张卡上的选项完全对齐：**不指定（自动择优）/ 按实时积分择优 / 随机（在合格账号里均匀抽签）/ 具体账号**。
- 随机档下，排除、禁用、冷却、模型冷却、在途已满的账号照常生效，只在合格候选里均匀抽签。
- 补了一道构建门禁：三个网关页的策略档位（含随机）与写回路径必须一致 —— 漏传直接构建失败，不会再「静默消失」。

## 🖥️ 在线演示修复：改名后全站空白

- 仓库改名后，在线演示站（GitHub Pages）打开只剩一个标题、页面全空白 —— Vite 的 base 还写死着旧仓库名，所有 JS 资源 404。构建、部署、工作流却全是绿灯，只能人肉点开线上地址才发现。
- 已改为**跟随仓库名**：以后仓库再改名，演示站自动跟随，不用改代码。
- 8 个 README 里失效的演示链接一并换到新地址，并补了 base 一致性门禁 + Chromium 实跑验证。

## 🔧 CI 修复（仓库改名后 Rust job 全红）

- cargo 缓存 key 带上仓库名：此前恢复出的 `target/` 记录的是**旧工作目录的绝对路径**，tauri 构建脚本按缓存指纹判定「无需重跑」，去找只存在于旧路径下的文件而失败。
- 关掉 `setup-rust-toolchain` 自带的 `target/` 缓存（它的 key 同样不含仓库名），缓存统一交给自家带仓库名的步骤。
- Clippy 失败时把诊断原文**抬成 check 注解**：job 日志下载需要管理员权限，此后 PR 页面直接可见真因，附带日志尾部（`Caused by` 之后才是真因）与 short 格式兼容修复。

## ♻️ 质量与内部

- 仓库改名后失联的 CI 环节全部恢复；`tsc` 与 7 项构建门禁全绿（`check:scope` 305 项全过）。
