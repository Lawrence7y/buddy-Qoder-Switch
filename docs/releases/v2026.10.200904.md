## ✨ Max Mode 开关：现在真的能关（接前端 + 后端）

上一版把「按各模型上限」做成了数据驱动，但开关只存在于原型里 —— 应用内始终开启。本次补齐真实链路：

- **网关页配置卡**新增「Max Mode（按各模型上限）」开关，默认开启，保存即生效（无需重启）。
- **开启**：对官方目录里 `max > dev` 的模型注入 `is_max_mode`，`/v1/models` 声明它自己的上限（glm-5.3 1M、mimo 982k…）。
- **关闭**：清单回到 `dev`（`__dev` 通道实际窗口），请求不再注入 —— 适合「先按默认窗口用」的场景。
- 三条入口（Trae 独立网关 / 统一网关 trae 命名空间 / web 管理面）读同一份配置，不存在「清单关了、请求还开着」的半截状态。

## 🛠 内部

- `TraeGatewayConfig` 新增 `max_mode`（默认 `true`，兼容 camelCase 别名）；读取用同步快照，拿不到锁按开启处理。
- `models_response_for` / `prepare_llm_chat_body` 显式接收该开关；`check:scope` 随签名更新，仍钉住「禁用集合是第二个实参」。
- 版本号统一为 2026.10.200904（19 处载体校验通过）。
